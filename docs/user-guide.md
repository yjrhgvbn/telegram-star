# 使用教程

Telegram Star 把已加入群组、频道中的关注内容收录到消息组，供你集中查看、标记完成，并按需转发通知。本文从首次登录开始，带你创建一条可验证的规则。

尚未启动服务，请先按 [README 安装说明](../README.md#安装) 操作；服务器配置、备份和更新见 [部署文档](user-deployment.md)。

## 使用前准备

- 一个可正常使用的 Telegram 账号，以及该账号已加入的群组或频道。
- 自己的 Telegram API ID 和 API Hash。
- 能连接 Telegram 的服务器网络。浏览器能打开 Telegram，并不代表运行后端的主机或 Docker 容器也能连接。
- 如需转发，准备一个自己的通知接收地址。Docker 镜像已包含 Apprise，无需额外安装。

**当前版本适合单用户自托管。** 一个后端共用一个 Telegram 登录会话，连接它的客户端共享消息、规则和转发设置。应用没有独立的访问账号、密码或多用户权限隔离；Telegram 登录用于连接消息来源，不能保护 Web 页面和 API。真实实例应放在可信网络，或有身份认证的反向代理之后，具体见 [访问与缓存](user-deployment.md#访问与缓存)。

## 1. 首次连接 Telegram

1. 用自己的 Telegram 账号登录 [my.telegram.org/apps](https://my.telegram.org/apps)，进入 **API development tools**，按页面要求创建应用并取得 `api_id` 和 `api_hash`。操作依据见 [Telegram 官方说明](https://core.telegram.org/api/obtaining_api_id)。
2. 打开 Telegram Star。部署在本机时访问 `http://localhost:3000`，远程部署时使用服务器地址。
3. 在“连接 Telegram”弹框中填写 API ID 和 API Hash，点击“保存配置”。如果已通过环境变量配置，页面会直接进入手机号阶段。
4. 输入带国家或地区代码的完整手机号，点击“发送验证码”。
5. 在 Telegram 中查看收到的登录验证码，填回页面后点击“登录”。
6. 如果账号启用了两步验证，按提示输入 Telegram 两步验证密码。

这里使用的是 Telegram 用户账号 API 凭据；通知机器人所用的 Bot Token 会在转发步骤中单独配置。

登录成功后，服务器会保存会话并在后续启动时尝试重连。页面保存的 API 凭据保存在数据库中；API Hash 不会通过配置状态接口返回明文。请保管好 `.env`、数据库、会话文件及备份，不要放进公开仓库或问题截图。

## 2. 创建第一条规则

下面用“版本更新”做示例。频道名称和消息文本仅作说明，你可以换成自己已有的来源与关键词。

1. 进入 **规则**，点击列表顶部的新建按钮，把规则命名为“版本更新”。
2. 在 **消息来源** 中选择一个自己已加入、近期有消息的群组或频道。可以按会话名称或 ID 搜索，也可通过消息内容发现来源。清空来源表示全部可用会话，首次配置时选一个来源更容易核对结果。
3. 添加一个关键词条件，输入以下内容，按逗号或换行分隔：

   ```text
   发布, 更新
   ```

4. 查看 **预览样本**。较窄屏幕需要切到“预览样本”页签；先扫描每个会话最近 50 条，没有结果时再适当扩大到 200、500 或 1,000 条。
5. 确认“匹配样本”中的原文确实是你需要的内容，点击命中证据可定位到对应条件组。需要过滤推广内容时，添加一个排除组，填入关键词“广告”。
6. 点击 **保存**，确认规则处于启用状态。随后新到达、符合条件的消息会进入 **消息 → 版本更新**。

这条规则表达的是：来源属于所选会话，正文包含“发布”或“更新”，且不包含“广告”。例如“项目更新：新增搜索功能”会匹配，“广告：今日更新优惠信息”会被排除。

### 条件如何组合

| 配置 | 实际含义 |
| --- | --- |
| 选择多个消息来源 | 来自其中任意一个；未选表示全部可用会话 |
| 同一关键词条件内的多个词 | 包含任意一个即可；不区分大小写，按文本包含匹配 |
| 同一个条件组中的多行 | 满足任意一行即可（OR） |
| 多个普通条件组 | 每一组都要满足（AND） |
| 排除组 | 组内任意条件命中，该消息就不收录 |

页面还支持正则表达式和 JavaScript 条件。第一次使用先把关键词规则跑通；按消息内容搜索来源只用于寻找会话，不会自动把搜索词加入规则。

**预览只检查样本，不会收录消息或发送通知。** “最近 200 条”是每个会话的扫描范围，不是全历史匹配总数。旧消息需要下面的历史补录。

**修改并保存条件，会重新计算当前规则已收录的历史消息，移除不再匹配的内容。** 其他规则仍收录的消息保留；一条消息没有任何规则归属后，其本地记录会被清除。删除规则也会清理相应归属，Telegram 原消息不受影响。

## 3. 补录已有的历史消息

1. 在已创建规则的详情页展开 **补录历史消息**。
2. 选择 **按数量**，先用“最近 1,000 条 / 会话”，或选择一个较小的自定义日期范围。
3. 点击 **开始补录**；如果规则有未保存修改，按钮会显示“保存并开始补录”，先保存当前条件再开始扫描。
4. 页面会显示已扫描、已命中和已保存数量。任务在服务器后台运行，关闭页面不会中断；服务器需要保持运行。
5. 完成后回到对应消息组，刷新列表查看收录结果。

手动历史补录**不会发送通知**。重复补录会跳过已经收录的归属；为已有消息新增当前规则归属也计入本次“已保存”，不表示多存了一份正文。“完整历史”的可扫描范围取决于当前账号实际可访问的 Telegram 历史，耗时取决于来源数量和活跃度。

## 4. 浏览与处理消息

每条监听规则对应一个消息组，“全部消息”会合并去重展示各规则收录的消息。目录用于整理消息组；规则名称在规则页修改。

- **标记完成 / 标记看完**：表示内容已处理，视频和视频留言使用“看完”文案。可以恢复为待完成；同一条消息在所有规则和客户端间共享完成状态。
- **打开原文或附件**：本身不会标记完成。你本人在 Telegram 对消息添加的表情反馈会同步为完成，因此手动恢复待完成后可能再次被同步完成。
- **搜索、状态筛选与批量处理**：批量操作仅针对当前查询已加载的消息，“全选”不会选中还没加载的历史。
- **查看媒体**：图片、文件和音频按类型展示；视频、视频留言和 GIF 使用“在 Telegram 查看”。设置里的“省流 / 均衡 / 清晰”控制服务器缩略图策略。
- **从当前规则移除**：只取消指定规则的收录，保留其他规则归属和 Telegram 原消息。手动补录通常可以重新收录；勾选“此规则以后补录时也跳过”后，该规则的后续手动补录也会跳过它。自动监听与自动回补会跳过已主动移除的归属。

在完成状态筛选下操作时，刚处理的消息可能暂留原位；重新筛选或刷新会读取最新结果。看到新消息提示时，点击提示才会跳转，便于保留当前阅读位置。

## 5. 配置 Apprise 转发

不配置转发，也可以正常收录和处理消息。需要通知时，先按 [Apprise 支持的服务](https://appriseit.com/services/) 文档准备接收地址。

以把通知发回自己的 Telegram 为例，使用自己的机器人 Token 和目标 Chat ID，地址形式如下。大括号内容必须替换为自己的值，不能直接使用：

```text
tgram://{BOT_TOKEN}/{CHAT_ID}
```

机器人创建、Chat ID 获取及地址参数见 [Apprise Telegram 文档](https://appriseit.com/services/telegram/)。接收者需要先与机器人建立会话，并确保机器人有权向目标发送消息。

1. 进入 **转发**，新建通道，填写名称和一个 Apprise 地址。
2. 在 **接收规则** 中勾选“版本更新”。也可以在规则页的“命中后通知”中选择该通道，两处维护同一关联。
3. 在 **消息格式** 中选择“简洁”“详细”或“Markdown”，也可直接编辑标题和正文模板。
4. 查看 **示例预览**。这里使用固定的示例消息，不发送，也不读取当前规则的真实消息。
5. 确认接收地址属于预期目标后点击 **发送测试**。它会使用当前地址和模板**真实发送一条示例通知**，无需先保存，测试成功也不会自动保存草稿。
6. 点击 **保存**，确认通道和监听规则都已启用。之后新命中的消息会按关联通道转发。

一个简单的自定义模板：

标题：

```text
[{{filterName}}] {{chatTitle}}
```

正文：

```text
{{content}}

时间：{{messageDate}}
原文：{{telegramLink}}
```

| 变量 | 内容 |
| --- | --- |
| `{{filterName}}` | 命中的规则名 |
| `{{matchedKeyword}}` | 命中信息；随关键词、正则或脚本条件而异 |
| `{{chatTitle}}` | 来源群组或频道名称 |
| `{{senderName}}` / `{{senderId}}` | 发送者名称 / ID |
| `{{messageDate}}` | 消息时间 |
| `{{content}}` | 消息正文 |
| `{{telegramLink}}` | Telegram 原文链接 |

标题模板最多 300 字符，正文模板最多 4,000 字符；这是模板输入长度，接收平台另有消息长度限制。空模板使用默认值，未知变量保留原文。Markdown 预设会生成 Markdown 文本，实际呈现还取决于接收平台及 Apprise 地址的格式参数。当前转发发送标题和正文，不上传原始媒体附件。

## 6. 连接其他客户端

浏览器直接打开服务端地址；桌面和 Android 从 [GitHub Releases](https://github.com/yjrhgvbn/telegram-star/releases) 下载对应安装包。macOS 打开 DMG 后将应用拖入 Applications；Windows 打开 EXE 安装；Linux 安装 DEB，或给 AppImage 执行权限后运行；Android 允许浏览器或文件管理器安装应用后打开 APK。

macOS 包未公证，首次打开可能需要在“系统设置 → 隐私与安全性”中允许；Windows 可能提示未知发行者。可下载的平台以该版 Release 附件为准。

客户端首次打开时填写服务端地址；后续可在 **设置 → 服务器连接** 修改，先测试，再保存。Android 使用 HTTPS 根地址。手机上的 `localhost` 指向手机本身，应填写手机能访问的服务器地址。

各端连接同一服务端后共享消息与配置。服务器地址保存在当前客户端，修改不会改变其他设备的连接配置。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 网页能打开，连接 Telegram 超时 | 检查后端所在主机或容器的 Telegram 网络连通性，以及 API ID / Hash。前端能访问后端，只说明 HTTP 连接正常。 |
| 没收到验证码或提示验证码无效 | 检查国际格式手机号，查看 Telegram 中收到的验证码；需要重新发起时返回手机号步骤。若 Telegram 提示等待，按提示等待后再试。 |
| 找不到消息来源 | 确认当前登录的是已加入该群组或频道的账号；来源选择面向群组和频道，不包含普通私聊。消息内容发现受 Telegram 搜索结果范围影响，可改用名称或 ID 搜索。 |
| 预览有结果，但消息页为空 | 预览不会保存消息。先保存并启用规则，再运行历史补录；完成后刷新消息列表。 |
| 关键词符合但没有命中 | 检查来源范围、其他 AND 条件组和排除组；适当增加预览扫描范围。图片里的文字不是正文关键词。 |
| 修改规则后历史消息减少 | 保存条件会重算当前规则历史归属。先查看条件和预览，必要时恢复条件后手动补录。 |
| 补录有消息，但没收到通知 | 手动历史补录不发送通知。用“发送测试”检查通道，再用后续新消息验证规则关联。 |
| “发送测试”失败 | 检查后端环境中 `apprise --version` 是否可用、地址凭据是否有效、接收权限和服务器到接收平台的网络；查看后端日志。 |
| 测试成功，新消息却没通知 | 确认通道草稿已保存、通道与规则已启用、接收规则已勾选，并在消息组中确认新消息确实被收录。 |
| 重启后再次要求登录 | 检查数据卷 / 会话文件是否持久化、目录是否可写，以及 Telegram 是否已撤销该会话。Docker 更新时不要使用 `docker compose down -v`。 |
| 另一设备没有更新刚移除的消息 | 主动刷新列表；从规则移除的结果不会主动广播到其他已打开页面。 |

提交问题时请提供运行方式、复现步骤、页面错误和脱敏后的相关日志。不要附上验证码、两步验证密码、API Hash、Apprise 完整地址、会话文件或真实数据库。
