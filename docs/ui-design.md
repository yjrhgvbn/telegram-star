# UI 设计基准

本文记录当前界面的公共规范、四个 Tab 的业务语义与交互边界。控件数值和行为细节以源码为准，构建及测试命令见[开发文档](user-development.md)。

## 产品表达

Telegram Star 按监听规则留下关注的 Telegram 消息，以消息组浏览，也可发送到转发通道。

- 保留来源、时间、原文、实体链接与附件形态；短通知、图片、视频、文件和语音按各自内容展示。
- 消息组是主要浏览上下文，“全部消息”是列表中的特殊消息组。
- “完成”表示内容已处理，视频与视频留言称为“看完”。底层字段为 `isRead`，不等同于打开或浏览过消息。
- 完成状态用文字、图形和颜色共同表达，已完成原文与附件保持正常可读。
- 页面以操作和内容为主，标题说明简短，同一配置使用一个编辑入口。

## 公共视觉与组件

四个工作区、登录、404、更新提示及 Portal 浮层共用根级白灰主题，使用 Geist Variable 和系统无衬线回退字体。

| 用途 | 视觉基准 |
| --- | --- |
| 工作区背景、桌面侧栏 | 浅灰 `#f8f9fa` |
| 内容、菜单、弹框 | 白色 `#ffffff` |
| 主文字、默认主操作 | 深灰 `#272b32` / `#30353d` |
| 主导航选中、消息操作与待完成 | 蓝色 `#3569a8`，配浅蓝反馈 |
| 已完成与成功 | 绿色 `#26795e`，配浅绿反馈 |
| 规则排除与警告 | 琥珀色 `#a5680b` |
| 错误与危险操作 | 红色 `#bf3e49` |

通过明度、字重和留白区分层级，分割线用于明确的区域边界；已有背景区分的列表不重复加线。消息行使用细分隔线，规则组用一层白色组框表达逻辑范围。普通保存按钮与菜单使用中性色，语义色限于对应状态和操作。

- 消息、规则、转发侧栏共用“左搜索、右新建”单行工具栏，不另占一行标题；规则无收起按钮，转发无刷新按钮。设置分类不需要搜索。
- 标题栏、配置保存、菜单使用共享尺寸；手机主要图标操作保持 44px 触控区域。
- 菜单与操作浮层靠近触发点，使用白色表面、8px 圆角、细边框与轻阴影；Dialog 使用共享遮罩和焦点约束。
- 键盘焦点可见，关闭浮层后恢复合理焦点。主导航及主列表 hover 仅在支持悬停的精确指针上生效。
- 状态与错误靠近操作区域；提交结果在编辑与预览切换后仍可见。操作完成不使用底部撤销浮层。

共享入口：[AppShell](../packages/web/src/components/AppShell.tsx)、[ListSearchToolbar](../packages/web/src/components/ListSearchToolbar.tsx)、[基础控件](../packages/web/src/components/ui)、[浮层样式](../packages/web/src/components/ui/overlay.css)。

样式组织：

- [index.css](../packages/web/src/index.css) 仅维护全局 token、基础元素与跨页面共享规则。
- 页面与组件专属 CSS 放在源码旁，由组件显式引入；媒体样式归属 `MediaPreview.css`。
- [AppShell.css](../packages/web/src/components/AppShell.css) 维护公共导航与消息蓝绿语义色；消息 Portal 需要显式附加 `.message-theme`。
- `.rules-theme`、`.forward-theme`、`.settings-theme` 是模块标记，不重复覆盖根级中性色。

## 导航、响应式与滚动

| 视口 | 主框架 | 侧栏 / 水平留白 | 标题栏 / 字号 |
| --- | --- | --- | --- |
| ≤680px | 单屏列表或详情，底部四项主导航，隐藏品牌 Header | 按内容紧凑排版 | 54px / 18px |
| 681–900px | 顶部导航，列表与详情并排 | 224px / 18px | 64px / 20px |
| ≥901px | 顶部导航，列表与详情并排 | 264px / 24px | 64px / 20px |

桌面保存按钮与菜单行高 36px，手机为 44px。手机详情提供返回入口，桌面详情标题不放返回按钮。消息搜索与筛选是独立工具行，保持在消息滚动区域之外。

| 主 Tab 根路径 | 手机 | 桌面默认详情 |
| --- | --- | --- |
| `/messages` | 消息组列表 | 全部消息 |
| `/filters` | 规则列表 | 首次读取时选定的规则 |
| `/notifications` | 转发通道列表 | 首次读取时选定的通道 |
| `/settings` | 设置分类 | 服务器连接 |

点击主 Tab 进入根路径；默认详情不改写 URL。规则与转发的默认对象在当前工作区保持稳定，后台新增或重排不替换它，删除后才回退到可用项。显式详情路径保持对应对象；根路径缩到手机后显示列表。

内容使用 `100dvh` 与独立滚动；纵向 flex 和 `min-height: 0` 逐层传递可用高度。底部导航基础高 64px，AppShell 通过 `--app-bottom-obstruction` 统一扣除导航和系统安全区，内部列表不重复预留。末项及操作菜单必须能滚动到导航上方。

业务布局使用独立边界：

- 规则在视口 ≥1280px 时编辑与样本并排；更窄时在详情内切换“编辑条件 / 预览样本”，681px 起侧栏仍常驻。
- 转发格式容器 ≥860px 时编辑与预览按 3:2 并排；更窄时切换“编辑模板 / 示例预览”。
- 消息容器 ≥700px 时带原文的视觉媒体左右排列；更窄时上下排列。≤639px 使用紧凑头像和条目间距。

## 保存、草稿与请求状态

已有配置无修改时禁用保存；新建规则或通道可提交字段校验。规则启停立即保存，转发启停属于待保存草稿。

- 规则在工作区内切换时暂存各规则草稿及编辑滚动位置；设置在分类切换和返回分类时保留各分类草稿。草稿不是刷新后可恢复的持久化数据。
- 离开规则或设置工作区、切换转发通道等会丢弃修改的操作需要确认；选择继续编辑保留输入，确认放弃只清理对应范围。
- 浏览器后退 / 前进由 [WorkspaceHistoryGuard](../packages/web/src/components/WorkspaceHistoryGuard.tsx) 处理，页面按钮保留自身离开检查，避免重复确认。规则与设置的同工作区历史切换保留草稿；转发确认放弃后重置编辑器。
- 刷新或关闭通过 `beforeunload` 提醒。保存、发送测试、删除等操作期间锁定相应编辑与离开入口，被阻止的历史导航不会在请求结束后补执行。
- 异步结果与发起时的对象、路由或服务器上下文绑定，晚到响应不能跳回旧页、清除新草稿或污染其他服务器数据。
- 规则、转发通道及接收规则清单区分读取中、失败、真正为空和搜索无结果；失败可重试，已有数据保留。

## 消息

入口：[MessagesFeature](../packages/web/src/features/messages/MessagesFeature.tsx)、[消息行与附件](../packages/web/src/features/messages/components)、[消息组操作](../packages/web/src/features/messages/components/FilterPanel.tsx)。

`/messages/all` 打开全部消息，`/messages/:filterId` 打开指定消息组。

### 消息组与目录

- 消息组来自监听规则，名称统一在 `/filters/:id` 编辑；消息页没有独立重命名或快捷编辑表单。
- 消息组可独立显示或移入目录，不强制归为“未分组”；没有收藏、“我的分组”“重点关注”视图、分组图标或数量徽标。侧栏时间表示最新消息时间。
- 目录可创建、改名、删除、上移和下移。删除目录后消息组独立显示，消息保留。
- “全部消息”可移动和排序，菜单不提供规则编辑。
- 移动与排序统一使用行旁浮层，不支持拖拽。上移、下移后浮层保持打开，支持连续操作；请求期间和首尾方向禁用。
- 独立消息组在后端占一个排序区块，不能逐个穿插在不同目录之间。

### 展示与处理

- 消息行占满内容区，正文左对齐、最大 800px；保留原文换行、实体链接、展开收起和真实文件名，不生成文章标题或摘要。
- 来源、状态、时间及更多操作位于消息头，正文和附件后放完成与 Telegram 入口。来源头像取频道或群组图片，无法加载时固定尺寸文字回退；不是单独查询发言人头像。
- 待完成为浅蓝标签与空心圆操作，已完成为浅绿标签与实心勾选。视频及视频留言使用“待看完 / 已看完”；单条按钮默认无底色。
- 打开 Telegram 或附件本身不会完成；本人 Telegram Reaction 同步仍会将消息标记完成，恢复待完成后也可能再次同步完成。
- 单条与批量支持完成、恢复待完成；批量仅作用于当前查询已加载消息。“全选”不会覆盖未加载内容。
- 在完成状态筛选内操作时消息暂留原位，重新筛选、搜索或刷新后读取最新结果。完成反馈直接反映在消息上，失败显示页内错误。
- 消息菜单可复制完整原文与原文链接。正文实体链接打开对应外链，不记录 Telegram 跳转或触发完成。
- 图片、视频、GIF、文件、音频按真实媒体类型展示。视频、视频留言和 GIF 通过“在 Telegram 查看”打开，不提供站内播放；没有原文链接时显示静态附件。
- 媒体与头像加载失败保留尺寸。无缩略图的视觉媒体仍使用预留区域，不会在加载后突然收缩为文件条。

### 浏览位置

搜索、筛选、顺序与“可见消息 ID + 行内偏移”按服务器和消息组保存到 `sessionStorage`，最多 100 组，不保存消息内容。返回组时恢复相应消息窗口；首次进入遵循规则自动定位，全部消息默认最新位置。失效锚点回退，主动刷新清除旧定位目标。

新消息提示只有点击后才跳转。分页和查询隔离旧请求，切组不让上一组结果覆盖当前内容。实际视口改变时对齐消息起点，滚动条引起的内容宽度变化保留行内偏移。

消息使用虚拟列表。修改字体、行距、附件尺寸或换行结构时，同步检查 [messageHeightEstimator](../packages/web/src/features/messages/utils/messageHeightEstimator.ts) 与实际测量，保护切组、展开、媒体加载和状态变化后的定位。

## 规则

入口：[FiltersFeature](../packages/web/src/features/filters/FiltersFeature.tsx)、[条件与预览组件](../packages/web/src/features/filters/components)、[条件工具](../packages/web/src/features/filters/utils.ts)。`/filters/:id` 编辑规则，`/filters/new` 新建。

### 条件模型与操作

| 层级 | 含义与表达 |
| --- | --- |
| 消息来源 | 限定所选会话；未选表示全部会话 |
| 不同条件组 | AND，必须分别满足；每组用一个白色组框 |
| 同组各行、同一条件的多个值 | OR；行前蓝色“或”比值之间的灰色“或”更突出 |
| 排除组 | 组内任意条件命中即排除，以浅琥珀关系栏表达 |

相同 `groupId` 构成一组，`groupEffect` 决定整组必须满足或排除；模型不支持任意层级嵌套。

- 标题、来源、条件组和添加入口共用淡冷色面板，即使条件很少也保持主要编辑区层次；外层无边框。
- 组内只保留必要字段边框和值 chip；单条件不预留左侧 OR 空列，不显示“条件 1”等编号或常驻教学说明。
- 组右上角“＋ 条件”连续添加备选，关系栏切换整组并且 / 排除并保留内容。排除组可多次添加，不要求位于最后。
- 类型支持关键词、正则、JavaScript。关键词按逗号或换行分隔，正则按换行分隔；保存包含尚未确认的临时输入。空关键词、正则及来源占位不进入持久化条件。
- 关键词与正则互切保留值，进出脚本模式清空不兼容字段。前端校验输入及脚本语法，实际匹配由服务端执行。
- 来源使用现有搜索弹框：会话名称 / ID 搜索、按消息内容发现、多选及清空为全部会话。选择过程保持列表顺序，关闭时恢复触发焦点。

### 预览与其他配置

- “匹配样本 / 排除样本”保留来源、时间、原文、打开 Telegram 与命中证据。扫描范围为每会话最近 50 / 200 / 500 / 1,000 条，数量不代表全部历史统计。
- 有效证据可定位对应条件组；窄屏先切回编辑。更新中、旧结果或请求失败时不允许旧证据定位新条件。
- “命中后通知”“打开消息时”“补录历史消息”以折叠设置行呈现。通知选择转发通道，补录未保存规则须先保存。
- **保存条件会重算历史消息并删除不再命中的内容。** 表单保留这一影响的简短说明。

## 转发

入口：[NotificationsPage](../packages/web/src/pages/NotificationsPage.tsx)、[通道编辑](../packages/web/src/features/notifications/components/TargetEditor.tsx)、[共享模板契约](../packages/shared/src/contracts/forward-targets.ts)。`/notifications/:id` 编辑通道，`/notifications/new` 新建。

- 详情分为“接收规则 / 消息格式”；顶部名称与 Apprise 地址直接点击编辑，展示地址原值。一个通道配置一个地址，服务类型由 Apprise 地址决定，不固定接收平台。
- “发送测试”使用当前地址和模板，无需先保存；实际会发送消息。保存、测试、删除期间锁定配置修改，保留搜索与查看，结果在页内反馈。
- 接收规则只有一份清单，提供搜索、“全部 / 已选 / 未选”及数量。左侧勾选，右侧展开真实来源与条件；查看不改变勾选，条件摘要保留 AND / OR / 排除语义。
- 批量操作仅影响当前搜索和筛选结果，保留范围之外的选择。规则行以留白区分，无逐行分割线或勾选后的整行底色。
- 格式使用横排“简洁 / 详细 / Markdown”一键切换，不设“格式预设”标题或下拉。模板不匹配内置项时显示“自定义”。
- 变量插入最后编辑字段的光标处，可替换选区并连续插入；未编辑过字段时插入正文末尾。
- 示例固定使用共享通用消息，不提供样本选择或模拟平台外观。预览直接展示实际发送的标题、正文和 Markdown 文本。
- 空白模板回退默认值，未知变量保留原文；标题最多 300 字符，正文最多 4,000 字符，预览与保存使用同一契约。

## 设置

入口：[SettingsPage](../packages/web/src/pages/SettingsPage.tsx)、[分类与表单](../packages/web/src/features/settings/components/SettingsForm.tsx)。四个分类为 `/settings/connection`、`telegram`、`media`、`clients`，`devices` 兼容设备分类别名。

- 分类栏不加搜索、装饰图标或重复状态。顶部保存只作用于当前分类，设备页提供刷新；表单最大 740px，设备清单使用剩余宽度。
- 服务器连接在当前客户端保存，可选择当前站点或自定义 HTTP(S) 地址。测试显示真实健康检查，不自动保存；空自定义地址不能隐式当作当前站点。
- 保存服务器地址时如有 Telegram 或媒体草稿，先确认放弃再切换。缓存与异步结果按服务器隔离。
- Telegram 与媒体分别保存、分别放弃，切换分类保留其他草稿。API Hash 原值不返回；数据库已有凭据时留空保留，环境变量凭据首次存入数据库需要新 Hash。保存凭据不代表切换当前账号。
- 媒体提供“省流 / 均衡 / 清晰”，控制服务器缩略图策略，不表示视频画质或自动播放设置。
- 设备列表支持搜索、类型筛选、最近活动与移除确认；最近活动是上报时间，不代表实时在线。当前设备不能移除，删除记录不等于退出登录，仍运行的设备可能重新注册。
- 当前设备和本机动作位于清单前，按真实 desktop / mobile bridge 能力显示；普通 Web / PWA 不展示原生动作。
- “更换客户端站点”返回壳连接设置，与仅修改当前页面 API 地址的服务器连接设置区分。重新加载与更换站点经过草稿离开保护，检查更新不代表下载安装。

## 登录、兜底与更新

- Telegram 登录使用共享 Dialog，保留配置、手机号、验证码与两步验证阶段。登录前不能用遮罩或 Escape 意外关闭；焦点约束在弹框内，提交期间锁定输入与返回。
- 来源选择使用相同 Dialog 外观，打开聚焦搜索，关闭恢复触发控件。
- 404 使用共享中性主题与按钮返回消息页。
- PWA 更新可用时提示，不自动刷新或抢焦点；位置读取 `--app-bottom-obstruction` 并额外留 12px 间距。
